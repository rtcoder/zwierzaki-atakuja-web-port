# Zwierzaki Atakują — browser port

## Intent

The user selected HTML and JavaScript in a browser as the target for a reverse-engineered port of the original mobile Java game. Preserve the recognisable original artwork, level geometry, ammunition, and gameplay. Deliver a playable private web application and maintainable source. The first verification milestone is the complete original first level, then the remaining recovered content.

## Decisions

- Plain HTML, CSS, ES modules and Canvas 2D, with no bundler or runtime framework dependency.
- Port simulation separately from rendering, controls, progression and storage.
- Reuse decoded original artwork without redrawing it or changing pixels.
- Ground-relative simulation coordinates: positive Y points down, ground is Y=0, target construction is near X=0.
- Preserve original gravity 200, nominal simulation increment 0.05 and source launch formulas. Keep wall-clock scheduling explicit; simulation timestep is not evidence of original rendering frequency.
- Preserve original level/ammunition data. A level may only be labelled original when it was recovered from its source definition.
- Support mouse, touch and keyboard. Keep default ammunition and support the five original animal types when present in recovered levels.
- Local browser persistence, versioned and tolerant of absent or malformed storage.
- No phone messaging, legacy purchase requests, or network dependencies at game runtime. Original paid extensions are outside the initial port.
- Host privately by default. This does not authorize changing audience to public.
- Any unimplemented special mechanics or lack of reference-run parity must be documented honestly.

## Approaches considered

The preceding Java/libGDX proposal is superseded by the user's HTML+JS choice. A Java emulator embedded in a page would run the old program but would not create the requested JS port. A fresh physics-based remake would be simpler but would change the recovered mechanics. The selected approach is a native JavaScript simulation and Canvas renderer based on analysis of the original bytecode and assets.

## Boundaries

`physics.js` owns bodies, collision detection and response. `levels.js` contains recovered level specifications. `assets.js` names and loads original images. `game.js` owns ammunition, aiming, shot state, damage, progression and replay. `renderer.js` owns camera and Canvas drawing. `main.js` maps DOM/input to game actions. `storage.js` owns local save validation. The renderer never decides whether a level is won.

## Validation

Pin recovered level-one geometry and ammunition. Test physics free fall, static/frozen bodies, ground contacts, rotated shapes and collision response. Test shot lifecycle, outcome transitions and storage parsing. Inspect the actual browser page and use real input to launch, pan, restart and exercise the mobile layout. Runtime parity with the original Java application is a distinct check; do not claim it based on unit tests or screenshots alone.
